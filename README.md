# Team Task Tracker v1.1

## Deploy
1. Replace files in the root of the GitHub Pages repository with these v1.1 files. No GitHub Pages settings change is needed.
2. In Firebase Console > Firestore Database > Rules, replace the rules with `firestore.rules` and Publish. **Firebase rules update required.**
3. Firebase Authentication authorized domain remains your GitHub Pages hostname. No authorized-domain change if the hostname is unchanged.
4. Existing Firebase users and data are preserved.

## Fixed
- Separate recipient/sender Firestore invitation listeners with UID filters.
- Member-scoped task listeners and manager-wide task listeners.
- Pending invitations surface in notification center.
- Team members can change task status to Pending/In Progress/On Hold/For Approval.
- Invitation decline updates work for recipients.

## Still requires trusted backend
- **Accept** transaction tries to update both task collaborators and invitation; Firestore rules intentionally block collaborator changes without server verification. Acceptance therefore remains incomplete in live mode.
- Automatic task-assignment and approval notifications cannot be generated by clients; Cloud Functions or a trusted backend is needed.
- Manager promotions/demotions require a secure backend and last-manager protection.
- Manager task updates must be restricted further before production.
- A member cannot necessarily see a task referenced in an invitation until acceptance; task previews may show 'Task unavailable'.

Do not deploy to production or open Firestore rules broadly to work around missing backend features.
